# ADR-002: Instagram-style database-generated sharded IDs
- **Status:** Accepted · 2026-11-15 (supersedes the ID-service design, doc 04 v0.1)
- **Context:** 10M cases/day per country require sharding. Reads must route by ID without a directory. The user wants IDs generated by the database, with the app passing only country.
- **Decision:**
  - 64 logical shards (schemas) per country index.
  - Per-shard PL/pgSQL `next_id()`: 41-bit ms time, 6-bit country, 6-bit shard, 10-bit sequence.
  - `next_case_no()`: 15 digits `CC-DDDD-HH-SSSSSS-K`.
  - Shard = `hash(grower_id) % 64`.
  - Details: `docs/syngenta/04_ID_GENERATION_DESIGN.md`.
- **Consequences:**
  - Plus: no ID service; routing by decode; globally unique keys simplify CDC merging.
  - Minus: ID known only after insert; DB clock dependency; 1,280 schemas to migrate.
- **Alternatives:** dedicated ID service (v0.1), UUIDv7 (no routing info, 16 bytes), plain sequences (no routing).
